# ChainTickets — Decentralized Event Ticketing System

> **Academic Project** · Decentralized Event Ticketing Using Smart Contracts with Anti-Scalping and NFT-Based Ticket Verification

---

## Project Overview

ChainTickets is a fully decentralized event ticketing platform built on Ethereum. Every ticket is an ERC-721 NFT minted directly to the buyer's wallet. Resale price caps are enforced inside Solidity smart contracts — not just frontend validation — making scalping economically impossible. Event staff verify tickets by scanning QR codes and redeeming them on-chain, permanently preventing re-entry.

---

## Problem Statement

Traditional ticketing is dominated by centralized intermediaries charging excessive fees, enabling secondary market scalping at multiples of face value, and issuing counterfeit tickets that cause fan losses. Verification at the door relies on easily forged paper/PDF tickets with no fraud prevention.

---

## Objectives

- Replace paper/PDF tickets with ERC-721 NFTs providing cryptographic ownership proof.
- Enforce anti-scalping resale price caps inside smart contracts, not just the UI.
- Enable instant on-chain ticket verification at event entry using QR codes.
- Give organizers transparent tools for event management and revenue tracking.
- Demonstrate academic application of Ethereum, Solidity, and Web3 frontend architecture.

## Blockchain Workflow

```
Organizer                 Smart Contract            Buyer
    │                          │                      │
    ├── createEvent() ────────>│                      │
    │   (title, price, cap)    │                      │
    │                          │<─── buyTicket() ─────┤
    │                          │     (msg.value)       │
    │                          ├── mint ERC-721 ──────>│
    │                          │                      │
    │                       [Later]                   │
    │                          │<─ listForResale() ───┤
    │                          │   (price ≤ cap)      │
    │                          │                      │
    │                          │<─ buyResaleTicket() ──── Buyer2
    │                          │   transfer NFT        │
    │                          │   pay seller          │
    │                          │                      │
Verifier                       │                      │
    ├── redeemTicket() ───────>│                      │
    │   (tokenId, eventId)     │                      │
    │                          ├─ mark redeemed        │
    │                          │  emit TicketRedeemed  │
```

## Smart Contract — EventTicketing.sol

### Key Functions

| Function | Description |
|---|---|
| `createEvent()` | Organizer creates event with price, supply and resale cap |
| `buyTicket()` | Buyer pays exact price, ERC-721 minted atomically |
| `listTicketForResale()` | Owner lists ticket; price validated against on-chain cap |
| `buyResaleTicket()` | Buyer pays seller; NFT transferred atomically |
| `redeemTicket()` | Verifier marks ticket used on-chain; prevents re-entry |
| `isTicketValid()` | View function: checks existence, event match, redemption |
| `setVerifierRole()` | Admin grants VERIFIER_ROLE to staff wallet |
| `grantOrganizerRole()` | Admin grants ORGANIZER_ROLE to organizer wallet |

### Security Design

- **Reentrancy**: All state-changing functions use `nonReentrant` guard.
- **Transfer restrictions**: `_update()` override blocks transfers of redeemed tickets; listed tickets can only be transferred through `buyResaleTicket()` (called by the contract itself).
- **Price cap**: `maxResaleBps` stored on-chain per event; enforced in both `listTicketForResale()` and `buyResaleTicket()`.
- **Double redemption**: `redeemed` flag checked before marking; revert with clear message on second attempt.
- **Role-based access**: OpenZeppelin `AccessControl` — no custom `onlyOwner` footguns.
- **Input validation**: All inputs validated in Solidity (not just frontend).
- **No private keys**: Zero private keys in source code; deployer key in `.env` only.

## Local Development

### 1. Start Hardhat Local Network

```bash
cd contracts
npm run node
```

This starts a local Ethereum node at `http://127.0.0.1:8545` with 20 pre-funded accounts.

### 2. Deploy Contracts Locally (new terminal)

```bash
cd contracts
npm run deploy:local
```

The deploy script:
- Deploys `EventTicketing.sol`
- Saves deployment info to `contracts/deployments/localhost.json`
- Copies ABI + address to `frontend/src/contracts/EventTicketing.json`

### 3. Configure MetaMask for Local Network

In MetaMask:
- **Network name**: Hardhat Local
- **RPC URL**: `http://127.0.0.1:8545`
- **Chain ID**: `31337`
- **Currency**: ETH

Import a Hardhat test account using its private key (shown in `npm run node` output).

### 4. Start Frontend

```bash
cd frontend
npm run dev
```

Open `http://localhost:3000`.

## Render Deployment

> Smart contracts live on the Ethereum blockchain — not on Render. Render hosts only the React frontend.

### Steps

1. Push your repository to GitHub (see GitHub section below).

2. Create a new **Static Site** on [render.com](https://render.com):
   - **Repository**: your GitHub repo
   - **Build Command**: `cd frontend && npm install && npm run build`
   - **Publish Directory**: `frontend/dist`

3. Add Environment Variables in Render dashboard:
   - `VITE_CONTRACT_ADDRESS` — your deployed Sepolia contract address
   - `VITE_CHAIN_ID` — `11155111`
   - `VITE_SUPPORTED_CHAIN_IDS` — `31337,11155111`

4. Add a Rewrite Rule (for SPA routing):
   - **Source**: `/*`
   - **Destination**: `/index.html`

5. Deploy. The `render.yaml` in the repo root automates this configuration.

## Known Limitations

1. **Image hosting**: Event images use external URLs (HTTPS or IPFS). IPFS gateways may be slow or unreliable. Production should use a pinning service.
2. **Ticket metadata on-chain**: Basic ticket data is on-chain; full NFT metadata URI (name, image, attributes) is not set in this academic version. Production would use `setTokenURI()` with IPFS-stored JSON.
3. **Gas costs**: Each `buyTicket` transaction requires a MetaMask confirmation. On mainnet, gas fees apply.
4. **Per-wallet ticket limit**: Set to 5 by default; configurable by admin.
5. **No fiat payment**: Only ETH is accepted. Production would require an on-ramp service.
6. **Local network state**: Hardhat local network resets on restart; redeploy contracts after each restart.
7. **QR camera**: The browser must have camera permission; some security configurations block it.
8. **Resale scanning**: Resale listings are found by scanning `TicketListedForResale` events from block 0, which may be slow on public networks. Production should use an indexer (The Graph).
